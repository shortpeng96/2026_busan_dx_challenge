# 🌊 임랑 해수욕장 수질 AI 예측 모델 — 데이터 분석 과정 정리

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| **해수욕장** | 임랑 해수욕장 (부산 기장군) |
| **목표** | 수질 기준 초과(입수 통제) 여부를 사전 예측하는 AI 분류 모델 개발 |
| **최종 성능** | ROC-AUC **0.808** (5-Fold 교차 검증) |
| **데이터 규모** | 93건 수질 검사 기록 (2014~2025), 양성(초과) 25건 (26.9%) |

---

## 2. 데이터 탐색 및 라벨링 수정

### 2-1. 초기 문제 발견
- 원본 수질 데이터에서 대장균(E.coli ≥ 500 CFU) 기준만 적용했을 때, **양성 샘플이 단 1건**밖에 없었음
- 이 상태에서 모델을 학습하면 AUC 0.873이 나왔지만, 이는 **1건의 양성 샘플에 대한 통계적 우연**이었음 (신뢰성 없음)

### 2-2. 라벨링 기준 재정립
- 임랑 해수욕장은 **장구균(Enterococcus)**에 민감한 해수욕장임을 발견
- 라벨링 기준을 `E.coli ≥ 500 OR Enterococcus ≥ 200`으로 변경
- **양성 샘플: 1건 → 25건 (26.9%)** 으로 증가, 통계적으로 의미 있는 학습 가능

> [!IMPORTANT]
> 라벨링 기준 수정이 이 프로젝트의 가장 핵심적인 전환점이었습니다. 양성 1건으로는 어떤 모델도 신뢰할 수 없습니다.

## 3. 데이터 수집 및 변수 구성 (단계별)

### 3-1. 기본 데이터 (AUC ~0.59)
| 데이터 | 출처 | 피처 수 |
|---|---|---|
| 수질 검사 | 해양수산부 해수욕장 수질 검사 | 대장균, 장구균, 날짜 |
| 기상 관측 | 기상청 종관기상관측(ASOS) | 기온, 강수량, 풍속 등 |
| 해양 부이 | 울산 해양부이(MEIS) | 파고, 수온, 파주기 등 |

### 3-2. 하수처리장 방류량 추가 (AUC 0.59 → 0.67)
| 데이터 | 출처 | 핵심 변수 |
|---|---|---|
| 기장 하수처리장 | 부산환경공단 | 당일 방류량, 1일 전 방류량, 3일 평균 방류량 |

> [!TIP]
> 임랑은 기장군에 위치하므로, 같은 기장군의 하수처리장 방류량 데이터가 수질 오염과 직결됩니다.

### 3-3. 전체 가용 외부 데이터 통합 (AUC 0.67 → 0.75)
| 데이터 | 출처 | 핵심 변수 |
|---|---|---|
| 기장 해양부이 | 기장 앞바다 MEIS | 파고, 수온, 파주기 (울산 부이와 교차 활용) |
| 정밀 조위 | 국립해양조사원 | 조차(tide_range), 1일 전 조차 |
| 해수 수온 | 기장 연안 수온 관측 | 표층 평균수온, 1일 전 수온 |
| 정밀 풍향/풍속 | 기상청 AWS | 풍향(sin/cos 변환), 1일 전 풍향 |
| 정관 하수처리장 | 부산환경공단 | 정관사업소 방류량 |

- 총 피처 수: **29개 → 97개**로 확대
- RFE(Recursive Feature Elimination)가 97개 중 **5개 핵심 피처** 자동 선별

## 4. 모델링 기법 (단계별)

### 4-1. 모델 아키텍처: Dual Ensemble
```
┌─────────────────────────────────────┐
│         Dual Ensemble 구조          │
├──────────────┬──────────────────────┤
│  Classifier  │  XGBClassifier       │ ← AUC / 경보 판단용
│  (분류기)    │  + RandomForest      │
├──────────────┼──────────────────────┤
│  Regressor   │  XGBRegressor        │ ← UI 시계열 차트용
│  (회귀기)    │  + RandomForest      │
└──────────────┴──────────────────────┘
```

### 4-2. SMOTE 양성 샘플 증강 (AUC 0.75 → 0.778)
- 25건밖에 없는 양성(초과) 샘플을 **SMOTE(Synthetic Minority Over-sampling Technique)**로 합성 증강
- **핵심 원칙**: 학습(Train) 폴드에서만 증강하고, 평가(Test) 폴드에는 절대 가짜 데이터를 섞지 않음 → AUC 신뢰성 보장

### 4-3. 상호작용 피처 실험 (역효과 → 롤백)
- `강수량 × 방류량`, `조차 × 풍향`, `CSO_Flag` 등 6개 상호작용 피처 추가 시도
- **AUC 0.778 → 0.764로 하락** (93건 소규모 데이터에서 노이즈로 작용)
- 즉시 롤백하여 원래 상태 복원

### 4-4. Optuna 하이퍼파라미터 자동 최적화 (AUC 0.778 → 0.808) ✅
- **100회 Trial** 자동 탐색 (TPE Sampler)
- 탐색 대상 파라미터:

| 모델 | 파라미터 | 탐색 범위 |
|---|---|---|
| XGBoost | 학습률 | 0.01 ~ 0.3 (log) |
| XGBoost | 트리 깊이 | 2 ~ 8 |
| XGBoost | 트리 수 | 50 ~ 800 |
| XGBoost | 서브샘플링 | 0.5 ~ 1.0 |
| XGBoost | L1/L2 정규화 | 0.001 ~ 10.0 |
| RandomForest | 트리 수 | 50 ~ 500 |
| RandomForest | 깊이 | 3 ~ 12 |
| RandomForest | 최소 리프 샘플 | 1 ~ 10 |
| 앙상블 | XGB 가중치 | 0.3 ~ 0.8 |

## 6. 최종 모델이 선택한 핵심 5개 변수

| 순위 | 변수명 | 의미 | 도메인 해석 |
|---|---|---|---|
| 1 | `precip_2d_sum_lag` | 2일 누적 강수량 (1일 지연) | 비가 오면 하수와 지표 오염물질이 바다로 유입 |
| 2 | `precip_5d_sum_lag` | 5일 누적 강수량 (1일 지연) | 장기간 비 → 토양 포화 → 오염물질 대량 유출 |
| 3 | `풍속(m/s)` | 기상청 관측 풍속 | 강풍 시 해수 혼합 → 오염물질 확산 패턴 변화 |
| 4 | `gijang_discharge_3d_mean` | 기장 하수처리장 3일 평균 방류량 | 하수 방류 → 대장균/장구균 직접 유입원 |
| 5 | `tide_range` | 조차 (만조-간조 수위 차이) | 큰 조차 → 해수 순환 활발 → 오염물질 희석/유입 |

> [!NOTE]
> **5개 변수 모두 해양환경학적으로 타당한 변수**입니다. 모델이 단순히 숫자를 외운 것이 아니라, 실제 오염 메커니즘(강수→유출→하수방류→해류확산)을 학습했음을 의미합니다.

## 9. 교훈 및 시사점

1. **라벨링이 모든 것의 시작**: 양성 1건 → 25건으로 바꾼 것이 가장 큰 성능 점프의 원인
2. **변수는 양보다 질**: 102개 피처 중 RFE가 고른 5개만으로 최고 성능 달성
3. **도메인 지식이 핵심**: 하수처리장 방류량, 조위 데이터 등 "바다 오염의 물리적 원인"에 해당하는 변수가 결정적
4. **상호작용 피처는 양날의 검**: 소규모 데이터(93건)에서는 오히려 노이즈로 작용
5. **하이퍼파라미터 튜닝의 마지막 한 방**: Optuna가 0.778 → 0.808로 마지막 벽을 돌파
